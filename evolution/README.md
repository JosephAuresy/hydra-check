# Hydra Check: evolution record

The historical record of the tool: what was tested, what was found, what was corrected, and how the numbers moved.

| File | What it is |
|---|---|
| `ledger/*.json` | One snapshot per file, named `<date>T<hhmm>_<label>.json`. Append-only: never edited or overwritten. |
| `milestones.json` | Hand-curated milestones (date, title, category, evidence, source). Add new ones as they happen. |
| `data.js` | Generated by `bench/snapshot.py` from the two above, so the page also works opened straight from disk. Do not edit. |
| `index.html` | The dashboard (single file, no external dependencies). Serve it with `python -m http.server` in this folder, or publish the folder. |

## Add a snapshot

```
python bench/snapshot.py --label "after mf6 rules" --note "what changed" --rescore
python bench/snapshot.py --list
python bench/snapshot.py --regen        # only after editing milestones.json
```

A snapshot records the git commit, the rules per family, the cheap Node test suites (run at that moment), the last saved precision-audit result (read, not re-run), the benchmark verdict matrix, and the model inventory. `--rescore` asks the current rules again about the saved faulted copies of the benchmark (read-only) so the benchmark column is current without rewriting the benchmark's own result files. Anything not available is written as "not recorded"; nothing is estimated. The script refuses to write absolute paths or user names.

Git is the history: commit each new ledger file together with `data.js`.

## Honesty rules

- Past states are reconstructed only from files that exist (git history, saved result files) and are marked `backfill`, with the sources named.
- The benchmark is development evidence on 22 faults; the rules were tuned after the first results, so before/after is not a blind test.
