    How to add a snapshot

    From the repository root, after the rules changed (and, if you want the benchmark column to be current, after bench/rescore.py, or use --rescore which asks the current rules again without writing anything in the work folder):

    python bench/snapshot.py --label "after mf6 rules" --note "what changed" --rescore

    To see what is already there:

    python bench/snapshot.py --list

    This writes one new file in evolution/ledger/ (never overwrites one), refreshes evolution/data.js and prints a summary. Commit the new ledger file and data.js. New milestones go in evolution/milestones.json; then run python bench/snapshot.py --regen.

    Limits of this evidence

    • Development evidence, not a validation. The numbers show that the fixes did what they were written to do on the cases that exposed the problems.
    • A pilot of 22 faults (plus 6 unmodified controls) on six base models, one per engine. "14 of 15" is a small count, not a rate with a confidence interval, and coverage is uneven across engines.
    • Rules were tuned after seeing the results. The "before" column is the first version of the rules, the later columns the improved ones; the improvements targeted the failures the first run exposed, so before and after is not a blind test. A fair test needs new faults and new base models that the rules never saw.
    • Faults are chosen, not sampled from the real distribution of user errors, and engine behaviour is what one run on one machine showed.
    • The audit is on models that ran. An error on a working model is a false-alarm candidate; the figures here are raw counts of error findings, and the 138 to 0 figures are the author's adjudicated result, quoted from the commit message.
    • Past snapshots are reconstructions. They use only files that exist (git history, saved result files). Whatever was not saved is marked "not recorded".
